# M-academy 3.2 — единый центр локальных данных

**Открыть:** https://gulyantsdanil-oss.github.io/m-academy/v3-data.html

## Что добавлено

- Чтение *без изменения исходных записей* из двух действующих локальных модулей: `macademy-v3-preview` (классы/недельный план) и `macademy-v31-workflow` (темы КТП/задания).
- Сводная аналитика классов, тематик, подготовленных заданий и недельного плана.
- Контроль качества: темы без целей, даты, литеры; задания без соответствующей темы; дубли темы; классы без совпадающего КТП.
- Наглядное сопоставление по номеру класса + литере + предмету. Неполные записи без литеры автоматически не связываются.
- Предварительный просмотр новых классов и датированных тем перед переносом из конвейера 3.1 в панель 3.0.
- Защита от дублей, лимитов и конфликтов изменений в другой вкладке.
- Общая резервная копия JSON *только для выгрузки*, без изменения прежних форматов, и отчёт CSV о замечаниях.
- Автоматический синтаксический/ссылочный контроль новой страницы через GitHub Actions.

## Важные ограничения

- Это **локальный мост**, а не backend. Не использует персональные данные и не синхронизирует записи между браузерами.
- Классы при переносе создаются для 2026–2027 учебного года. Перед реальным развёртыванием год должен стать контекстом школы и настраиваемым серверным полем.
- Синхронизация сейчас **односторонняя и добавочная**: КТП 3.1 → классы и недельный план 3.0. Исходные темы КТП сохраняются без изменений. Привязанные учебные материалы и назначения не копируются.
- Не записывать в демосайт ФИО детей, пароли или иные чувствительные школьные данные.
- JSON-архив 3.2 объединённый, но предыдущие формы восстановления ожидают свои отдельные версии. Для восстановления пользоваться экспортом соответствующего модуля до разработки единого безопасного импорта.

## Как проверить

1. Открыть 3.1, добавить тестовую тему с номером, литерой, предметом и датой.
2. Открыть 3.2; увидеть тему в статистике и замечания по качеству.
3. Нажать «Сформировать предварительный просмотр»; проверить создаваемый класс и урок.
4. Подтвердить перенос и открыть 3.0 → «Классы» и «План недели».
5. Вернуться на 3.2 и повторить предварительный просмотр: дубликаты не должны появиться.
6. Проверить скачивание объединённого JSON и CSV-отчёта.

## Следующий системный этап

Расширить `backend/pilot-app` авторизованным интерфейсом классов/КТП, сохранить привязки в PostgreSQL, проверить RLS в разных школах и связать реальные задания с темами. Настройка таблиц **не является** единственным оставшимся этапом — отдельно потребуются сервер, авторизация, миграции, тесты, резервирование и проверка обработки персональных данных.
