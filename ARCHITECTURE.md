# M-academy — целевая архитектура школьной платформы

Дата: 2026-11-23. Статус: **проект архитектуры**, не реализация.

## Цели

1. Сохранить работающие пользовательские сценарии публичного прототипа, не переписывая весь продукт одновременно.
2. Защищённые роли: администратор школы, учитель, ученик. Права должны проверяться на сервере, а не в HTML/JavaScript браузера.
3. Перенос КТП, КСП, заданий и прогресса ученика из локальных JSON-структур в управляемое хранение с резервными копиями.
4. Поддержка нескольких школ только после полноценного теста внутри первой школы и анализа требований к защите персональных данных.

## Рекомендуемая последовательность

### Фаза 0 — стабилизация публичной беты

- Провести 29 сценариев `qa.html`.
- Исправить блокирующие регрессии (маршруты тем, импорты, DOCX, восстановление данных).
- Вынести общий генератор в `math-engine.js` (сделано), поддерживать unit-тесты на математические ответы и крайние случаи.
- Версионировать форматы резервных копий; `local-backup-v1` и `local-backup-v2` должны читаться.

### Фаза 1 — защищённая серверная основа

Вариант архитектуры для оценки: Next.js + TypeScript, PostgreSQL, серверная авторизация (выбранный провайдер под требования учреждения), API и ограничение доступа по ролям. Выбор хостинга и страны хранения данных **только после проверки правовых требований РК** и политики школы.

```text
Браузер (публичный каталог / урок / личный кабинет)
                 ↓ HTTPS
Backend API / серверная валидация / аудит событий
                 ↓
PostgreSQL (школы, классы, КТП, КСП, задания, результаты)
                 ↓
Резервные копии и контроль доступа
```

Минимальные сущности:

- `schools(id, name, region)`
- `accounts(id, role, school_id, status)`
- `teacher_class_assignments(teacher_id, class_id, subject_id)`
- `classes(id, school_id, grade, label, academic_year)`
- `curriculum_plans(id, teacher_id, class_id, subject_id, academic_year)`
- `curriculum_topics(id, plan_id, position, title, learning_objective_codes, hours, date)`
- `lesson_drafts(id, topic_id, teacher_id, revision, content)`
- `ksp_documents(id, teacher_id, class_id, topic_id, revision, content)`
- `assignments(id, teacher_id, class_id, topic_id, variant_seed, state)`
- `submissions(id, assignment_id, student_id, submitted_at, score)`

Все отношения между школами, учителями и классами проверяются сервером. Клиентский выбор `school_id` не является достаточным основанием для доступа. Не хранить и не сравнивать пароли самостоятельно в браузере.

### Фаза 2 — перенос данных и ролей

1. Создать управляемый импорт старых JSON резервных копий с режимом предварительного просмотра.
2. Переносить только данные текущего учителя, после подтверждения правильности привязки к классу и предмету.
3. КСП сохранить по форме приказа № 130 с разделением официальных целей обучения и целей конкретного урока.
4. Включить серверное хранение, версионирование, журнал изменений, восстановление и экспорт.
5. Провести тесты разграничения доступа: учитель A не видит материалы учителя B, ученик не видит ключи педагога, администратор видит только разрешённую организацию.

### Фаза 3 — проверка первой школы и масштабирование

- Пилот: одна школа, ограниченная группа педагогов.
- Проверка законности обработки персональных данных несовершеннолетних и условий локализации данных на момент внедрения.
- Нагрузочное тестирование, резервирование и восстановление, доступность с телефона.
- Только затем — подключение других школ.

## Ограничения текущей версии

- GitHub Pages обслуживает статические файлы и не заменяет backend.
- Личный кабинет — демонстрационный, данные в localStorage доступны пользователю этого браузера.
- Ссылки на ученические варианты не являются защищёнными контрольными.
- Ответы в скриптах браузера не скрыты криптографически — это допустимо для тренажёра, но не экзамена.
- Сводный каталог из 342 пунктов не равнозначен 342 готовым урокам.
- Сведения об официальных целях обучения нужно поддерживать по действующим нормативным документам.

## Критерий завершения

«Финальная школьная версия» означает, что аутентификация и права доступа проверяются сервером, данные безопасно хранятся и резервируются, формы КСП и КТП протестированы, а сценарии учителя/ученика прошли эксплуатационную приёмку. Качество интерфейса само по себе этого не гарантирует.
