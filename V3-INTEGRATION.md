# M-academy 3.0 — единый центр и контракт подключения

## Статус 25.11.2026

- `v3.html` — новый единый интерфейс версии 3.0 на GitHub Pages.
- Переключатель «Учитель / Ученик / Администратор» управляет **только демонстрационным представлением**, НЕ полномочиями.
- 15 карточек существующих модулей открывают рабочие страницы, а серверный пилот ведёт к исходному коду.
- «Классы» и «План недели» сейчас локальные пробные данные. Из браузера можно экспортировать/импортировать JSON v3.
- Настоящие учётные записи, синхронизация, оценки, публикация заданий и доступ к данным классов **не работают** на GitHub Pages.

## Что необходимо, чтобы подключить реальные таблицы

В репозитории **уже существуют** миграции `backend/supabase/migrations/*.sql` и приложение `backend/pilot-app` (Next.js + TypeScript + Supabase). Не создавайте параллельную базу в v3.html. Используйте существующие миграции и API защищённого приложения.

| Модуль | Таблицы / интерфейсы | Примечания |
| --- | --- | --- |
| Организации и пользователи | `schools`, `memberships`, Supabase Auth | Роли назначаются доверенным администратором, не из браузера |
| Классы | `classes`, `class_teachers`, `class_students` | Требуются проверки владения школой и прав |
| КТП | `curriculum_plans` | Импорт из локального Excel/Word нужно валидировать и переносить в JSONB |
| Уроки | `lesson_drafts` | Важно не терять ревизии |
| КСП | `ksp_documents` | Использовать проверку конфликта редакций |
| Задания | `assignments`, `assignment_questions`, `assignment_keys` | Ответы не показывать ученикам до завершения |
| Сдача и оценивание | `submissions`, `submission_answers`, `submission_grades` | Только через проверенные RLS/RPC |
| Файлы | Защищённое объектное хранилище (ещё не подключено) | Нельзя выкладывать файлы учеников в публичный репозиторий |

### Порядок интеграции

1. Развернуть отдельный серверный пилот (публичный GitHub Pages не запускает Node.js и API).
2. Создать и настроить Supabase-проект в допустимой по требованиям хранения данных инфраструктуре; применить и проверить миграции.
3. Настроить Auth и первичное доверенное назначение администратора; запретить публичную запись ролей.
4. Прогнать RLS-тесты для admin/teacher/student и негативные сценарии между школами и классами.
5. Сделать в Next.js единый авторизованный портал по дизайну v3 и подключить чтение/запись классов, КТП, КСП и заданий. **Не** вставлять service-role key в публичный JS.
6. Добавить серверное хранилище, журнал действий, резервные копии, восстановление и инструкции по удалению данных.
7. Пройти математическую/методическую приёмку, security review и проверку соответствия требованиям к персональным данным, прежде чем приглашать реальных учеников.

### Для подключения КТП

Сначала использовать тестовые учебные данные без ФИО. Таблица КТП `curriculum_plans` хранит JSONB в `content`, а не произвольные столбцы копируемых Excel-листов. Каждую строку нормализовать до полей `number`, `topic`, `hours`, `date`, `learning_goals`. Пользователь должен подтверждать результат импорта перед сохранением.

## Приёмка демонстрационной v3

- Открыть `v3.html` с GitHub Pages.
- Проверить 3 роли и переходы во все модули.
- Добавить фиктивный класс, сохранить и обновить страницу: локальная запись сохраняется.
- Добавить фиктивный урок в план.
- Экспортировать JSON, очистить демоданные, импортировать файл и проверить восстановление.
- Проверить на телефоне и браузере Windows.
- Подтвердить отдельно: реальные роли/авторизация **ещё не подключены**.

## Важное ограничение

«Остаётся подключить таблицы» не означает, что после ввода ключа система безопасно заработает: помимо таблиц нужны работающие серверные API, авторизация, RLS, секреты только на сервере, миграции, хранение файлов и проверка доступа.
