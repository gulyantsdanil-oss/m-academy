# M-academy — изолированный серверный пилот

## Подтверждённая архитектура

Публичный GitHub Pages (`https://gulyantsdanil-oss.github.io/m-academy/`) остаётся демонстрационной статической версией. **Next.js-приложение находится в `backend/pilot-app` и не работает на GitHub Pages.** Настоящий вход и SQL требуют отдельного HTTPS-хостинга и Supabase.

## Шаги развёртывания после разрешения владельца

1. Создать отдельный тестовый Supabase-проект без данных школьников. Применить SQL из `backend/supabase/migrations/` в порядке имён; проверить историю миграций до повторного применения в существующей базе.
2. Создать проект для веб-хостинга Next.js (например, Vercel), связанный только с `gulyantsdanil-oss/m-academy`; указать **Root Directory: `backend/pilot-app`**, framework Next.js, Node.js 22. Не направлять проект на GitHub Pages.
3. В настройках хостинга указать **только публичные** `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` (publishable/anon ключ); секрет `SUPABASE_SERVICE_ROLE_KEY` не добавлять в Next.js клиентский проект и никогда не делать `NEXT_PUBLIC_*`.
4. Записать настоящий HTTPS-origin размещения в `PILOT_SITE_URL`, выполнить `npm run auth:preflight`. Команда не обращается к Google, лишь проверяет структуру URL и выдаёт адреса для дальнейшей регистрации.
5. После подтверждения владельца включить Google OAuth Provider в Supabase, задать разрешённые redirect URLs и настроить OAuth Client в Google Cloud Console. Проверить точный callback `https://<supabase-project>.supabase.co/auth/v1/callback` и возврат в корень **развёрнутого** Next.js.
6. Назначить три **взрослые тестовые** учётные записи для ролей администратор, учитель и ученик, согласно `backend/pilot-app/scripts/bootstrap.mjs`. Служебный ключ использовать только в доверенном терминале при явном подтверждении тестового режима.
7. Выполнить по очереди Google-вход каждого аккаунта и проверить `/auth-check`, `/admin/roster`, цепочку КТП → урок → задание → ответ → оценка, а также отрицательные сценарии (нет роли, чужая школа, чужая оценка, повторная отправка).
8. Только после юридического и технического согласования можно обсуждать подключение настоящих школьных данных.

## Инструменты диагностики

- `GET /api/health` — только проверка, что Next.js отвечает. JSON `{"status":"ok","service":"m-academy-pilot"}`; **не подтверждает** доступность Supabase или работоспособность OAuth.
- `npm run build`, `npm run start -- -p 3117`, `node scripts/http-smoke.mjs http://127.0.0.1:3117` — локальная проверка собранного сервера и восьми страниц.
- `npm run auth:preflight` — автономная структурная проверка URLs; не печатает публичный ключ и не проверяет реальное владение доменом.
- `.github/workflows/pilot-ci.yml` — автоматические тесты, TypeScript, сборка, HTTP smoke, тестовая PostgreSQL, RLS и резервное восстановление.

## Границы безопасности

Пилот возвращает HTTP-заголовок `X-Robots-Tag: noindex, nofollow`, запрещает встраивание во фрейм и ограничивает передачу referer. Это не аутентификация и не достаточная защита для размещения реальных персональных данных. Критичные данные защищаются серверными политиками PostgreSQL (RLS), которые должны быть повторно проверены в целевом Supabase.

**Не завершено:** сам деплой, настройка реального Google OAuth, администрирование уже приглашённых аккаунтов, аудит законодательства Казахстана о персональных данных несовершеннолетних и тестовые браузерные сценарии.

## Переносимый Docker-пакет (серверный Next.js)

Серверная сборка настроена на `output: 'standalone'` и упакована в `backend/pilot-app/Dockerfile` (Node.js 22, отдельная стадия сборки, запуск от пользователя UID 1001). Контекст `.dockerignore` исключает `.env`, локальные зависимости, сборочные файлы. Этот контейнер нужен для тестового серверного хостинга, **не для GitHub Pages**.

Пример **только для временных публичных тестовых параметров**:

```bash
cd backend/pilot-app
docker build --build-arg NEXT_PUBLIC_SUPABASE_URL=https://test-project.supabase.co \\
  --build-arg NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_disposableci \\
  -t m-academy-pilot:local .
docker run --rm -p 3000:3000 m-academy-pilot:local
```

Откройте `http://127.0.0.1:3000/api/health` для проверки запуска. Используемые здесь адрес и ключ **не соответствуют реальному проекту**, поэтому вход не заработает. В реальном пилоте подставляются только URL конкретного тестового Supabase и его **публичный** ключ. Параметры `NEXT_PUBLIC_*` в Next.js встраиваются в клиентский код при сборке: для смены проекта нужна **пересборка образа**. Не передавайте в build-args служебный или секретный ключ, реальные приватные данные либо OAuth client secret. Постоянное размещение также требует TLS (HTTPS), безопасного домена, управления образами и журналами, автоматических перезапусков.

GitHub Actions теперь выполняет отдельный `container-smoke`: собирает образ с синтетическими публичными значениями, запускает контейнер без root, проверяет `/api/health` и основные маршруты. Это тест **портативности и старта**, а не реального соединения с Supabase или Google OAuth.
